# 无限画布 · AI 短剧工作台

本地优先的 React Flow + FastAPI + SQLite 工作台，按照《无限画布开发文档.docx》开发。`generate_tool` 是 RunningHub 云端生成工作流脚本，不是本地模型推理。

代码目录、生成调用链、缓存版本和维护入口见 [架构与维护指南](docs/架构与维护指南.md)。

## 启动

需要 Node.js（建议 22 LTS 或更新兼容版本）、pnpm 10、Python 3.11+、uv。

```powershell
pnpm install
uv sync --project services/backend
# 尚无 .env 时创建；已有配置不要覆盖
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
pnpm dev
```

启动器打开带本次会话的工作台；访问后地址中的 token 会清除，媒体使用 HttpOnly 会话。请勿分享 `.runtime/session.json`。运行期间保留启动器，按 Ctrl+C 退出并清理子进程。也可 `pnpm build` 后运行 `python scripts/dev.py --serve` 使用单端口工作台。

`.env` 配置：

- `RUNNINGHUB_API_KEY`：RunningHub 账号密钥。原脚本内的硬编码密钥已移除。
- `TEXT_API_BASE`、`TEXT_API_KEY`、`TEXT_MODEL`：支持 `/chat/completions` 的文本服务。BASE 包括服务商要求的 `/v1` 等前缀，不包括 `/chat/completions`。未配置时手动编辑故事，文本生成节点会说明未就绪。
- `FFMPEG_DIR`：同时包含 `ffmpeg.exe`、`ffprobe.exe` 的目录，或将工具加入 PATH。
- `CANVAS_DATA_DIR`：可选项目根目录，默认仓库内 `data/`。每个项目独立 `project.db` 和 `assets/`；数据库备份不代替媒体备份。

## 创作流程

1. 创建项目，在左侧添加故事节点并编辑文本。
2. 导入角色/场景参考图；在「角色 / 场景」中建立设定，将锁定版本的参考节点加入画布。
3. 添加分镜图节点，连接文本与图片。图片节点右键可创建关联的视频节点。
4. 在设置中配置服务凭据、模型价格和并发；项目左下角开启云端生成后运行选区或画布。提交前显示费用估算并确认，未知价格明确标记；真实请求可能扣费。选择 ComfyUI 的节点在本地服务执行。
5. 在属性栏比较、采用候选版本；批准视频后加入时间线。导入/生成音频后添加配音或音乐，再输入字幕和起止时间。
6. 调整 V1 主轨、V2 叠加轨及 A1 对白、A2 音乐轨的起点、源入点、时长、音量与淡入淡出。合成预览生成含混音和字幕的低分辨率视频；导出 MP4 保存于项目 `exports/`，附输入清单与校验 hash，有字幕时也保存 SRT。

画布支持缩放、空格拖动平移、Shift 框选、Ctrl+Z 撤销、Ctrl+Shift+Z 重做、Ctrl+D 复制、Delete 删除、Ctrl+S 保存。画布和时间线自动保存。窗口关闭前有未保存内容时会提示。

生成节点属性中的「覆盖缓存」默认关闭，优先复用相同输入的结果。开启后，运行该节点会重新调用服务并更新缓存，历史素材保留；作为依赖的上游仍可复用缓存。设置随节点保存，适用于运行节点、选区或画布；「重新生成」按钮也可单次强制生成。

视频提示词扩写会补充人物站位、视线目标、开口与倾听反应，区分固定摄影机与人物静止，避免把三视图姿态照搬进视频。它保留原剧情、台词及刻意回避视线等要求，并要求模型自检动作与时长冲突；实际表演质量仍需生成后审核。

分镜视频流程：**提取分镜 → 分镜选择 → 视频提示词扩写 → 生成视频**。提取的每条分镜严格为 4–15 秒；“分镜选择”连接上游文本后，在节点或属性栏选择一条，可添加多个选择节点分别处理不同分镜。选择在本地执行，不调用大模型；上游条目内容变化后需重新选择。所选时长同步到下游扩写和视频节点，实际运行时以上游时长为准。

“视频提示词扩写”使用所选文本服务，读取仓库根目录 `ref-en.txt` 的完整规则，输出六段英文：`subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music`。对白和画面中的文字保留原语言。可直接输入文字，也可连接参考图片或勾选图片素材；传图片时须选择支持 `image_url` 输入的文本模型。图片按连线顺序、再按勾选顺序编号为 `<Picture 1>` 等，下游视频节点须接入相同图片并保持相同顺序；扩写文本节点不会替你转发图片。暂不直接发送音视频给文本服务，可在补充要求中填写其参考编号和角色。

视频统一使用「生成视频」节点，默认使用 `workflow_json_new.py` 的 MiniMax H3 完整工作流，按实际参考素材数量自动匹配：1–9 张图片，可额外搭配 1 段音频或 1 段视频（视频模板使用视频音轨）。超出默认模板支持的组合会明确提示，可在设置中配置并选择其它视频工作流；不再提供默认 LTX / Wan 模型。自定义全能参考完整工作流可将提示词、图片、视频、音频按映射传入，最多 9 张图片、3 段音频、3 段视频；连接后自动出现下一参考端口，必填素材由工作流决定。分镜图支持 Image2.0 文生图及 1–8 张参考图。音频使用「音频素材」节点导入和引用，不再提供新建音效、配音生成入口；旧项目中的对应节点保留兼容。模型权限、时长、费用以云服务实际响应为准。

## 验证

```powershell
pnpm typecheck
pnpm build
pnpm test
```

浏览器验收必须启动独立服务，禁止使用日常 `pnpm dev` 会话。终端一：

```powershell
pnpm --filter desktop exec playwright install chromium
pnpm build
$env:FFMPEG_DIR = '你的 FFmpeg bin 绝对路径'
uv run --project services/backend python scripts/qa.py
```

启动器创建独立 `.runtime/qa-*` 数据/设置目录，不读取 `.env` 或日常凭据，并打印会话文件路径。保持终端一运行；终端二使用该路径：

```powershell
$env:CANVAS_QA = '1'
$env:CANVAS_SESSION_FILE = '启动器打印的 session.json 绝对路径'
$env:FFMPEG_DIR = '你的 FFmpeg bin 绝对路径'
pnpm test:browser
pnpm test:performance
node scripts/audit-browser.mjs
# 也可使用隔离的本机 Chrome 进程，不读取个人浏览器资料：
$env:TEST_BROWSER_PATH = 'C:/Program Files/Google/Chrome/Application/chrome.exe'
```

完成后在终端一按 Ctrl+C 停止服务，测试数据保留在对应 QA 目录。缺少隔离标记、清单字段、独立数据/设置路径，或使用 5173 日常端口时，写入脚本直接失败。清单是可信本地启动配置，须使用该启动器生成，不要手工指向日常服务。

媒体验收需将 `FFMPEG_DIR` 设置到当前测试进程环境，然后运行 `pnpm test`。测试会实际合成五镜头 15 秒竖屏 MP4，验证 H.264/AAC、时长、字幕文件和完整解码。未配置 FFmpeg 时该项明确标记跳过；不能据此声称媒体通过。

测试使用独立 Mock Provider 和 HTTP 契约桩，不会发起收费生成。真实云端生成需要本机配置并在 UI 中提交。完整任务和外部验收状态见 [完整开发文档](docs/完整开发文档.md)。

`pnpm verify` 先强制检查 ffmpeg/ffprobe 可执行，再执行语法/类型、前端构建、前端与脚本回归和后端测试；显式错误的 FFMPEG_DIR 会直接失败。`pnpm lint` 是语法和类型检查，不是代码风格检查。`pnpm test:browser` 验证真实编辑流程；`pnpm test:performance` 测量 200 节点/300 边，报告保存在 `.runtime/qa/`。浏览器检查需要上述独立 QA 服务。

## 设置、迁移与本地模型

### 多个文本服务商与模型

1. 打开「设置 → 生成服务」，在「文本服务商」中点击「添加文本服务」。
2. 填写名称和兼容 Chat Completions 的服务地址，例如 `https://你的服务商/v1`。不要包含 `/chat/completions`。
3. 添加该服务商支持的模型 ID，选择默认模型，再保存设置。模型列表由用户维护。
4. 在当前服务下填写密钥，点击「保存此服务密钥」。每个服务有独立的系统凭据，不共用默认文本服务的环境变量密钥。
5. 选择「剧本扩写」或「提取分镜」节点，在右侧分别选择「文本服务商」和「文本模型」。同一画布的不同节点可选择不同服务或模型。

原单文本服务和 `TEXT_*` 环境变量继续对应「默认文本服务（兼容原配置）」。停用服务会阻止新任务选择它，已入队任务保持原地址和模型；撤销密钥后任务明确报凭据缺失，不会切换到其他服务。

误建的空配置或不再使用的服务，可以通过「移除此服务配置」从草稿移除，保存设置后生效。移除配置不会自动撤销系统密钥；需要撤销时，先使用该服务的「撤销此服务密钥」。底部「恢复已保存设置」可撤回尚未保存的配置修改或删除，并重新读取已保存预算；已单独保存的密钥不会因此撤销。

### 多个图片和视频工作流

队列分为 LLM 文本、图片＋视频、音频及本地输入处理，各自使用独立执行线程。在「设置 → 费用与并发 → 同时运行任务」配置「图片＋视频并发数」及「LLM 文本并发数」（1–8）。例如图片＋视频设为 3，表示两类任务合计最多占用 3 个名额；LLM 不占用这些名额。已提交但仍在云端排队的任务也占用名额，轮询不会重复提交。降低并发会等待现有任务释放名额；节点之间的输入依赖仍需满足。旧图片、视频并发配置会合并为总额度，上限 8。

1. 在「设置 → 生成服务」保存 RunningHub 密钥。
2. 打开「设置 → 云端工作流」，选择内置 Image2、LTX 2.3、Wan 2.2，或复制、新增自定义配置。
3. 自定义配置填写名称、适用节点，选择「完整工作流 JSON」，粘贴 API 格式完整图，再填写输入映射和输出节点 ID。节点必须包含 `class_type` 和 `inputs`；不接受编辑器格式的 `nodes/widgets_values`。RunningHub 工作流 ID 可留空，沿用脚本默认占位值。已有配置也可继续选择「云端工作流 ID」。
4. 保存后，在图片或视频节点右侧「生成工作流」中选择。选择「默认工作流（兼容原配置）」仍按原 `generate_tool` 自动匹配。
5. 开启项目左下角的云端生成，填好提示词和所需参考素材后运行。

表单里的素材序号从 1 开始，导入 JSON 的 `index` 从 0 开始。每个传入素材都需要对应映射，未映射素材或缺少必填输入会阻止提交。固定种子填写在「固定参数」中；需要每次随机时添加来源为「随机种子」的映射。

自定义工作流可通过「移除此工作流配置」移除，保存后生效；内置工作流保留。导入配置包时会使用与保存相同的校验规则。也可直接导入原始 API 格式 JSON，生成待完善的草稿，再选择适用节点、填写映射和输出节点后保存；原始图不会自动猜测提示词或输出节点。此校验不联网运行工作流，也不产生生成费用。

完整图模式直接调用 `generate_tool.rh_process_generate.rh_api_generate_by_workflow`：先上传参考素材，再将提示词、素材文件名等写入任务副本的 `inputs`，序列化整个图提交。未映射的参数、节点连接及元数据保留。返回任务 ID 后继续轮询并下载所选输出节点的结果。完整图随任务冻结，后续编辑不会改变已排队任务。配置包可在下例基础上添加 `workflow` 字段（完整图对象或 JSON 字符串），此时 `workflowId` 可省略。

新增工作流默认使用完整 JSON 模式。填写后可点击「检查当前工作流」单独验证格式、输入映射和输出节点；检查不保存设置，也不调用云端。修改配置后原检查结果会清除，需要重新检查。在当前「云端工作流」页内切换完整图与 ID 模式，会按配置分别保留 JSON 草稿；离开该页、关闭设置或恢复已保存设置后，模式切换备份会丢弃，请先切回完整图并保存需要保留的内容。

可在「导入工作流配置 JSON」中导入以下结构。示例的工作流及节点 ID 是占位值，须换成你自己的实际 ID；这不是可直接运行的云端工作流。

```json
{
  "id": "my-image-workflow",
  "name": "角色分镜图",
  "kinds": ["image.generate", "image.variation"],
  "version": 1,
  "enabled": true,
  "workflowId": "替换为实际工作流ID",
  "nodeInfoList": [
    { "nodeId": "4", "fieldName": "steps", "fieldValue": 20 }
  ],
  "mappings": [
    { "source": "prompt", "nodeId": "2", "fieldName": "text" },
    { "source": "image", "nodeId": "3", "fieldName": "image", "index": 0, "required": false }
  ],
  "resultNodes": ["9"]
}
```

视频配置使用 `kinds: ["video.image_to_video"]`，按云端节点添加 `image`、`seconds`、`fps` 等映射。导入会建立新的本地配置 ID，避免覆盖已有配置。工作流和服务配置保存在本机；项目导入到其他机器后，若缺少所选配置，应重新选择，应用不会静默替换。

在「费用与并发 → 模型价格」中，通过「选择报价对象」按工作流名称或“服务商 / 模型”选择，点击「添加价格」，填写单价、单位和币种后保存。系统自动使用对应报价键；仍可手动填写旧规则。独立配置键为 `workflow/<配置ID>` 或 `text/<服务ID>/<模型名>`。显式选择的配置不会套用其他工作流或服务商的同名价格；未配置价格时显示费用未知，启用预算后会阻止提交。

任务入队时固定工作流模板、文本地址、模型、报价及凭据引用；修改设置不改变正在排队的任务。切换配置或修改模板会产生独立缓存，避免返回其他配置的结果。密钥不写入任务快照或项目包。

文本服务返回密钥/权限错误、模型或地址不存在、参数拒绝、限流时，会显示对应原因并释放本次费用预留，不会自动重发。修正密钥后可以手动重试；若修改了服务地址、模型、提示词或工作流，应重新运行节点，原任务的重试仍使用原冻结配置。服务器错误、网络中断或响应格式异常仍可能已经产生费用，会保留预留并提示核查服务商账单。

默认和自定义云端工作流都在预留费用及提交前检查输入参数；例如 Image2 超过 8 张参考图时会在本地终止。撤销已有文本服务密钥是独立操作，即使其他配置草稿未填写完整也能执行，不会顺带保存或丢弃这些草稿。

「设置」可保存或撤销 RunningHub 和文本服务密钥；Windows 使用系统凭据保管库，页面只返回配置状态。环境变量优先于保管库，撤销界面密钥不会删除环境变量。公开设置位于 `%LOCALAPPDATA%/InfiniteCanvas/settings.json`，可通过 `CANVAS_CONFIG_DIR` 隔离。

价格由用户按实际合同录入，支持每任务/每秒及 CNY/USD；运行前估价，提交前原子预留。项目预算启用时，未知价格、币种不符、额度不足会阻止提交。估算和预留不是服务商结算账单，`actual` 保持未知；远端失败或提交不确定仍可能收费。并发按文字、图片、视频、音频分别限制。

项目工具支持 ZIP 导出/导入：携带数据库与媒体和 SHA-256 清单；导入创建新项目并重映射引用，不覆盖原项目。模板只带画布定义和参数，不带媒体和凭据，导入后需重新绑定素材。ZIP 不替代日常独立备份。

ComfyUI 需自行安装模型和节点并启动本机服务（通常 `http://127.0.0.1:8188`）。设置中导入带版本、API prompt 和字段映射的工作流模板，再执行连接/节点/模型诊断；节点属性中选择本地 Provider。适配器仅连接 loopback，不自动下载模型。模板结构与校验示例见 `services/backend/tests/test_comfy.py`。未安装真实模型时仅能验证 HTTP 契约。

画布支持选区分组/解组及撤销；角色设定包括外貌、服装、授权音色、多参考图和限制，可绑定剧集、剧情场景及分镜。节点属性可比较两份候选后采用版本。

## Windows 桌面壳

桌面壳为 Tauri 2，子进程启动本地服务，窗口加载随机 loopback 端口。关闭桌面应用时终止本地服务；未完成远端任务在租约过期后恢复查询。

构建需安装 Rust stable、MSVC C++ Build Tools，并准备 FFmpeg 发行版（bin 下有 ffmpeg.exe、ffprobe.exe，上一级有 LICENSE、README.txt）。

```powershell
powershell -ExecutionPolicy Bypass -File scripts/package-sidecar.ps1
pnpm --filter desktop tauri dev
# 发布构建
pnpm --filter desktop tauri build
```

打包前设置 `FFMPEG_DIR` 指向发行版 bin 目录；脚本将工具及许可说明收集到安装包。先生成 sidecar 后才能运行 Tauri（bundle 配置需要对应目标平台的二进制）。开发壳使用项目虚拟环境；安装包使用 PyInstaller sidecar，不要求终端用户安装 Python，并自动使用安装目录 media 中的 FFmpeg（显式设置 FFMPEG_DIR 时以其为准）。安装版默认使用系统应用数据目录，`CANVAS_DESKTOP_DATA_DIR` 可指定绝对路径作隔离验收。WebView2 是运行条件，安装器按需安装；本项目不分发模型或签名证书。

`package-sidecar.ps1` 可独立生成 Windows x64 后端 exe；已验证该 exe 能启动 Worker 并提供内嵌前端。桌面壳/安装包的实际验证情况以开发文档执行记录为准。

## 当前边界

Windows 首版已实现 ZIP/模板、系统凭据、费用预算、多模态并发、本地模型适配、多轨合成、角色场景设定和分组。全功能 NLE（光流、关键帧、多机位）、云账户/协作、模型市场和 macOS 不在原文首版范围。真实云计费闭环、真实 ComfyUI 生成、证书签名和独立干净机器仍需外部验收条件；不能以 Mock 或本机安装测试代替。

## 安装验收与发布

```powershell
node scripts/desktop-smoke.mjs <安装包绝对路径>
python scripts/release.py <安装包绝对路径>
```

安装验收在 `.runtime/desktop-qa-*` 下静默安装并用真实 WebView2 验证保存重开、关闭进程树和卸载。只对测试进程开启调试端口，日常运行默认不开启。发布工具在 `.runtime/release/` 生成 SHA256SUMS、依赖锁文件校验及包清单、签名状态和本地证据。安装包未签名时明确为 `NotSigned`。CI 定义位于 `.github/workflows/ci.yml`；只有远程运行成功后才能声称 CI 通过。

RunningHub 的远端取消能力未在原脚本提供，取消只停止本地采用与后续调度，不保证停止远端计费。提交响应不确定时不会自动重发，必须先核查云端任务后显式重试。素材软删除保留物理文件，缺失引用会阻止执行与导出。
