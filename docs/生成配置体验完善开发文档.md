## 开发文档：生成配置管理体验完善

### 背景
多配置功能已完成，但未填完的草稿无法移除、错误导入会污染表单、报价需要手填配置 ID，影响实际配置体验。

### 目标
- [x] 用户可移除误建或不用的服务、工作流配置，并在保存前撤回到已保存状态。
- [x] 导入前执行完整模板校验，错误配置不会进入设置草稿。
- [x] 按工作流或服务商与模型名称选择报价对象，自动填入正确报价键。

### 涉及文件
| 文件路径 | 操作类型 | 说明 |
|---------|---------|------|
| `services/backend/tests/test_generation_profiles.py` | 修改 | 导入校验接口回归 |
| `services/backend/app/main.py` | 修改 | 只校验、不保存、不联网的工作流接口 |
| `scripts/smoke.mjs` | 修改 | 草稿移除、错误导入、价格选择及恢复交互测试 |
| `apps/desktop/src/GenerationProfiles.tsx` | 修改 | 移除配置和严格导入校验 |
| `apps/desktop/src/Settings.tsx` | 修改 | 按名称配置价格、恢复已保存草稿 |
| `README.md` | 修改 | 说明新增管理操作和报价流程 |

### 方案与边界
- 延续用户已确认的多工作流/多文本服务设计，本轮修复配置管理过程中的缺口，不增加新服务协议。
- 移除按钮仅改本地草稿，保存设置后生效；原有节点显示配置失效，不静默替换。已排队任务保留原冻结配置。移除服务不自动撤销其系统密钥，避免影响已提交任务；用户可在移除前主动撤销。
- 设置底部增加“恢复已保存设置”，从本机重新读取设置和预算，并清空当前配置编辑状态；不会撤销已单独保存的密钥。
- 导入新工作流先生成新本地 ID，再向校验接口提交整个模板；验证通过才加入草稿。接口调用只验证结构，不联系 RunningHub、不提交任务。
- 价格列表新增按名称选择的对象目录，包含内置/自定义工作流与服务商模型。保留手工报价键入口以兼容旧节点类型价格规则。
