## 开发文档：多工作流与多文本服务选择

### 背景
用户需要预先配置多个图片、视频工作流及多个文本服务商和模型，并在生成节点中独立选择。

### 目标
- [x] 图片、视频节点可选择已保存且兼容当前节点的工作流。
- [x] 文本节点可分别选择服务商和该服务商下的模型。
- [x] 配置持久化、密钥隔离、任务快照及报价随选择正确变化。
- [x] 保留已有内置工作流和单文本服务配置的兼容性。

### 已确认方案
推荐集中维护配置列表、节点保存稳定配置 ID。相比每个节点重复填写地址和密钥，此方案便于维护和复用；相比仅增加一个全局切换器，此方案允许同一画布不同节点使用不同服务。

#### 用户操作
1. 设置中的“文本服务”显示服务商列表，支持新增、编辑和停用。每个服务商包含名称、兼容 Chat Completions 的地址、独立密钥、模型列表和默认模型。
2. 设置中增加“云端工作流”列表，支持命名、复制、新增、编辑和停用。以现有 RunningHub 为云端后端，保留 generate_tool 内置工作流，并支持配置自定义工作流 ID、输入映射、固定参数和输出节点。
3. 自定义工作流提供表单配置和配置 JSON 导入；仅有工作流 ID 无法确定提示词、参考图等参数位置，必须同时提供映射。
4. 图片、视频节点属性中显示兼容的工作流选项；文本生成节点显示“服务商”和“模型”两个选择框。切换服务商时选择其默认模型。
5. 现有本地 ComfyUI 入口继续使用现有配置；本轮重点是多个云端工作流及多个文本服务商，不新增其他云端协议适配。

#### 数据和执行
- 文本服务配置具有稳定 ID、名称、地址、模型列表、默认模型及启用状态；密钥按服务 ID 存入系统凭据管理器，不写入项目或任务快照。
- 工作流具有稳定 ID、名称、适用节点类型、版本、内置适配器或自定义 RunningHub 模板；模板声明提示词、图片、视频、时长等输入映射及输出节点。
- 对每个选择在入队前校验：配置存在、已启用、类型兼容、模型属于服务、输入数量和映射合法。错误配置直接提示，不提交收费任务。
- 入队时冻结工作流模板、文本地址及模型、凭据引用、版本和报价；执行和结果下载使用冻结配置。编辑或停用配置只影响未来任务，不使旧任务静默改用其他服务。
- 缓存键包含所选工作流或文本服务及其执行参数；不同配置不误用缓存。凭据删除后旧任务明确报告凭据缺失，不回退到其他服务密钥。
- 新配置报价使用工作流 ID 或服务商 ID + 模型名区分，避免同名模型跨服务商串价；旧配置继续使用已有价格规则。未知费用保留现有预算拦截机制。
- 旧文本配置作为默认服务保留；旧节点未显式选择时使用兼容默认项，旧任务快照继续可执行。

### 风险点
- RunningHub 自定义工作流的节点和字段不同，需要明确的输入及输出映射，不能只更换工作流 ID。
- 多服务商仅覆盖现有 Chat Completions 兼容协议；独有协议需要另外适配。
- 本轮不自动获取在线模型列表，避免配置时产生外部依赖；模型列表由用户维护。
- 服务商或工作流停用后，旧节点要显示原选择失效，不能静默切换。
- 当前仓库尚无提交；遵守全部任务完成后才能提交的规则，不提前提交设计文档。

### 执行接口约定
- `textServices`：`{id,name,baseUrl,models,defaultModel,enabled}[]`；凭据名为 `text-<id>`，节点保存 `textServiceId`、`textModel`。原配置以 `legacy` 默认服务呈现。
- `cloudWorkflows`：`{id,name,kinds,version,enabled,builtin?,workflowId?,nodeInfoList?,mappings?,resultNodes?}[]`。内置 Image2、LTX、Wan 工作流在目录中提供；用户可复制为独立配置。
- 自定义 `mappings` 项为 `{source,nodeId,fieldName,index?,required?}`，source 支持 prompt、image、video、audio、seconds、fps、seed；媒体 index 从 0 开始。固定参数使用 `nodeInfoList`。
- 节点保存 `workflowId`；任务保存 `cloudWorkflow` 冻结副本，适配器根据冻结模板构建上传、提交和输出筛选请求。
- `GET /api/v1/generation-options` 提供可选工作流和文本服务及就绪状态，不返回密钥。
- 独立报价键为 `workflow/<id>`、`text/<服务id>/<模型名>`；显式新配置不回退到其他服务的同名模型报价。
- 后端定向验证：`uv run --project services/backend pytest services/backend/tests/test_generation_profiles.py -q`；完整验证 `pnpm verify`；界面验证 `pnpm test:browser`，使用隔离配置目录及独立 Chromium。
