## 开发文档：数据目录异常反馈优化

### 背景
检查设置、自动保存和任务恢复代码后，优先修复数据目录保存失败反馈不清楚和已修复错误重复显示的问题。

### 目标
- [x] 配置写入失败时返回可理解的错误，并保留上次配置。
- [x] 成功保存或撤销后清除已处理的启动回退提示。

### 涉及文件
| 文件路径 | 操作类型 | 说明 |
|---------|---------|------|
| `services/backend/tests/test_project_storage.py` | 修改 | 复现配置写入异常与过期提示 |
| `services/backend/app/project_storage.py` | 修改 | 将写入异常转换为明确错误 |
| `services/backend/app/main.py` | 修改 | 成功更新后重置启动错误 |

### 任务清单（必须全部标记完成）
- [x] 任务 1：增加回归测试；输入原子替换失败和启动回退状态，输出对旧配置保留、错误信息和再次读取状态的断言；确认修改前失败。
- [x] 任务 2：改进目录配置写入错误处理；输入磁盘或权限异常，输出明确错误；验证旧配置仍有效、临时文件清理。
- [x] 任务 3：清除已解决的启动错误；输入成功保存或撤销，输出再次 GET 不含旧错误；失败时仍保留原提示。
- [x] 任务 4：运行后端回归与差异检查，记录结果。

### 验收标准
- [x] 写入失败不会清空旧配置或向页面泄露底层异常堆栈。
- [x] 保存与撤销成功后重新打开设置不再看到过期错误。
- [x] 测试通过，日常项目数据不被修改。

### 风险点
- 仅修改异常反馈，不自动迁移数据、不改变目录切换生效时机。
- 目录本身可写不代表系统配置位置可写，需分别反馈。
