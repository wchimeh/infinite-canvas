## 开发文档：视频参考音频校验修复

### 背景
最近视频任务的音频只输入生成节点，扩写未收到音频却生成了音色引用；同时配套视频音轨被误解释为独立音频，可能造成声音引用失配。

### 目标
- [ ] 允许音频只接视频生成；扩写未收到音频时不编造音色或原话，明确模型音频能力。
- [ ] 视频提交前校验真实扩写音频与实际输入的内容、顺序及音频标签编号；兼容旧稿及下游独立音频。
- [ ] 保持视频音轨与对应视频配对，拒绝孤立配套音轨，并明确界面用途。

### 验收标准
- [ ] 未向扩写提供音频时，可保留用户明确的下游音频占位；生成时校验真实音频数量。
- [ ] 扩写用 A 音频而生成用 B 音频、顺序改变或加入音轨导致编号偏移时，在云端视频提交前拦截。
- [ ] 稀疏视频端口与配套音轨不会错误配对；独立参考音频仍正确送入 `ref_audios`。
- [ ] 编辑稿保留来源；旧扩写或未收到音频的扩写可使用生成节点独立连接的音频。
- [ ] 保留用户工作流模型和采样设置，不擅自替换源录音、不重新发起收费生成。

### 风险点
- 音色参考是生成条件，不能保证逐字复现源录音；严格保留原音轨属于不同功能，本次不擅自启用。
- 未运行云端模型，也未对生成视频做语音转写；可以证明链路错误，不能宣称模型输出质量已被实测修复。
- 最近样例使用的是独立参考音频，不存在配套音轨；配对问题是检查中发现的另一处缺陷，不把它冒充该样例的直接原因。
- 提供的工作流采用 Ref2VA 主模型和 FL2V 8-step LoRA；是否影响音频遵循需要模型侧对照实验，本次保持用户原配置。
