## 开发文档：武打节点检查修复

### 背景
检查发现6步默认配置使SelfLift切换点等于总步数，且默认参数修改未更新缓存版本。

### 目标
- [x] 保留默认6步、速度1、武打0.35，使SelfLift切换点合法。
- [x] 新任务不复用旧默认参数缓存。
- [x] 参考视频按H3原生24fps解释规则加载，避免非24fps视频节奏变化。

### 涉及文件
| 文件路径 | 操作类型 | 说明 |
|---------|---------|------|
| `services/backend/tests/test_combat_video.py` | 修改 | 切换点边界、fps及版本回归 |
| `services/backend/app/combat_video_workflow.py` | 修改 | SelfLift有效切换点与参考帧率 |
| `apps/desktop/src/CombatVideoSettings.tsx` | 修改 | 最少2步及准确的默认值说明 |
| `services/backend/app/generation_profiles.py` | 修改 | 工作流缓存版本升级 |

### 任务清单（必须全部标记完成）
- [x] 任务 1：补充回归；输入2/6/7/10/16步及视频，输出切换点小于总步数、24fps和新版本断言。
- [x] 任务 2：修复适配器；输入步数，输出min(6, steps-1)，最少2步；参考视频force_rate为24。
- [x] 任务 3：修复界面边界与说明；输入步数编辑，输出最少2步且默认6步。
- [x] 任务 4：更新缓存版本；输入新任务，输出版本2快照，与旧参数缓存区分。
- [x] 任务 5：验证；输入修复结果，输出后端回归、前端构建和浏览器验证。

### 验收标准
- [x] 默认261.steps=6，397.transition_step=5；1步明确不支持，2步切换点1。
- [x] 已有显式步数与强度不擅自替换；不触发实际云端生成。
- [x] 新任务版本2，已有远端任务仅继续获取原结果。
- [x] 普通音频、视频及图片映射仍正确，无示例素材残留。

### 风险点
- 此修复消除静态可确认的参数错误，不代表远端自定义节点及模型资源已验证可用。
- 自定义采样器要求低分辨率和高分辨率阶段至少各一步，因此不支持1步。
- 对非24fps参考视频按24fps重采样，保持参考动作的实际时间尺度。
