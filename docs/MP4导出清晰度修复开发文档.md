## 开发文档：MP4 导出清晰度修复

### 背景
用户反馈正式导出的 MP4 比原片段模糊，需要降低二次编码损失并修复画幅切换后的旧尺寸残留。

### 目标
- [x] 正式导出提高细节保留，预览继续使用轻量参数。
- [x] 修改画幅时同步片段布局，显示实际输出尺寸。

### 涉及文件
| 文件路径 | 操作类型 | 说明 |
|---------|---------|------|
| `services/backend/tests/test_export_quality.py` | 新建 | 真实视频画质回归 |
| `services/backend/app/timeline.py` | 修改 | 避免普通片段经过 RGBA 往返转换 |
| `services/backend/app/exporter.py` | 修改 | 正式导出编码质量 |
| `apps/desktop/src/timelineLayout.test.mjs` | 新建 | 画幅修改布局回归 |
| `apps/desktop/src/timelineLayout.ts` | 新建 | 纯函数同步片段尺寸 |
| `package.json` | 修改 | 持续验证布局回归 |
| `apps/desktop/src/Timeline.tsx` | 修改 | 接入画幅同步并明确像素尺寸 |

### 任务清单（必须全部标记完成）
- [x] 任务 1：新增真实 FFmpeg 画质回归；输入细节测试视频，输出源与导出的 PSNR 比较，记录旧行为失败。
- [x] 任务 2：修复普通不透明片段转换；输入片段透明度和淡入淡出，输出保持 YUV 的普通片段或保留透明合成的特殊片段；验证叠加及淡入淡出不回归。
- [x] 任务 3：提高正式导出质量；输入正式/预览标记，输出正式 CRF 16 / medium 编码、原预览参数；通过真实画质回归。
- [x] 任务 4：提取当前仅修改宽高的逻辑为函数并新增画幅布局回归；输入已保存和未保存的片段、叠加片段，输出目标尺寸及位置断言，确认旧行为无法满足。
- [x] 任务 5：实现布局同步函数；输入原时间线及新宽高，输出新布局且不修改原对象；通过布局测试。

- [x] 任务 7：在画质测试文件补充透明度、淡入和淡出像素回归；输入真实白色视频，输出预期亮度，防止透明合成回归。
- [x] 任务 8：把布局测试加入 package.json 的 verify；输入验证命令，输出自动运行的新测试。
- [x] 任务 9：运行媒体、时间线和前端回归，记录结果并更新验收。

### 验收标准
- [x] 同尺寸真实视频导出相较旧流程的细节保真度提升，宽高及帧率保持。
- [x] 多轨叠加、音频、字幕和预览测试通过。
- [x] 从竖屏切换横屏时，原全屏片段占满新画布，叠加层按比例调整，原文档不被原地修改。
- [x] 构建通过；无需调用云端或修改用户项目。

### 风险点
- 更高质量编码增加文件大小和处理时间，仍属于有损压缩，不承诺完全无损。
- 未取得用户原始片段与导出文件，不能断言本次反馈仅由编码参数导致；错误画幅、源视频清晰度也会影响结果。
- 不自动修改已有项目画幅；用户需选择匹配素材的横竖比例并重新导出。
- 不在本任务重新打包 EXE，已安装版本需后续打包更新。
