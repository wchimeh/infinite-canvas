## 开发文档：多角色逐张生成入口修复

### 背景
实际任务提取了 7 个角色，但用户将整份提取结果连接到单个角色图节点，最终只生成一张图。

### 目标
- [x] 提供明确的一键拆分并逐张生成全部角色入口。
- [x] 拦截单图节点误用多角色列表；场景列表同类问题同步处理。

### 涉及文件
| 文件路径 | 操作类型 | 说明 |
|---------|---------|------|
| `services/backend/app/worker.py` | 修改 | 在缓存和提交前检查多项提取结果 |
| `apps/desktop/src/Inspector.tsx` | 修改 | 提取结果与直连生图节点展示拆分生成操作 |
| `apps/desktop/src/App.tsx` | 修改 | 确认/复用独立节点并提交全部目标任务 |
| `services/backend/tests/test_characters.py` | 修改 | 多角色/场景不错误提交单图 |
| `scripts/characters-smoke.mjs` | 修改 | 验证一键提交全部角色且不重复创建 |

### 任务清单（必须全部标记完成）
- [x] 任务 1：worker 检查图节点上游结构化角色/场景列表；多于一项时报明确拆分提示，单项正常生成，禁止旧合图缓存绕过检查。
- [x] 任务 2：Inspector 对提取结果及直连图节点显示人数/场景数和生成全部入口，运行中禁用；复用既有审核内容。
- [x] 任务 3：App 确认时返回对应独立节点；同一任务重复执行复用角色/场景记录与节点，缺失节点可重建；生成全部只运行这些节点，不运行其它画布节点。
- [x] 任务 4：后端测试多项输入不提交、不命中合图缓存，单项允许；浏览器验证 run 的 nodeIds 覆盖全部角色且重复操作不增加节点。
- [x] 任务 4b：浏览器模拟 7 个角色，从直连图节点首次生成全部；验证创建 7 个独立节点、提交全部 ID 并继承所选工作流。
- [x] 任务 5：构建、完整回归、空闲重启并恢复工作台，记录实际问题与操作入口。

### 验收标准
- [x] 7 个角色对应 7 个独立角色图任务，沿用同时一个角色图的调度规则。
- [x] 多项列表直连单图不会再付费误生成一张合图。
- [x] 重复确认不重复创建，生成入口可处理已确认角色。
- [x] 测试通过，不自动消耗用户额度重跑现有任务。

### 风险点
- 拆分后的节点固定本次审核的角色/场景描述；新提取结果需要重新确认。
- 已完成的错误合图保留历史，不自动删除或再生成。
- 场景生成继续使用已配置媒体并发，角色图才固定串行。

### 验证记录
- `pnpm verify` 通过：语法、类型检查、生产构建及 200 项后端测试；保留现有包体积与依赖弃用警告。
- 浏览器角色回归通过：首次拆分 7 个角色并继承工作流，提交全部独立节点；重复点击复用节点；提取节点与直连图节点入口均可用。
- 场景、结果操作、任务状态回归通过。浏览器业务写入均模拟，没有付费生成调用。
- 确认队列空闲后重启本地服务，主页与定义接口返回 200，已重新打开工作台。
- 操作入口：选择提取角色或直连的生成角色图节点，点击“逐张生成全部角色”。
