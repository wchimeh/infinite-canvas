## 开发文档：批量生成入口优化

### 背景
批量生成按钮缺少工作流选择和批次进度，用户不容易判断本次生成内容与提交状态。

### 目标
- [x] 角色与场景统一提供数量、视图说明、工作流选择和批次状态。
- [x] 生成中阻止重复提交，保留已采用图片和独立节点编辑内容。

### 涉及文件
| 文件路径 | 操作类型 | 说明 |
|---------|---------|------|
| `apps/desktop/src/BatchGeneration.tsx` | 新建 | 批量操作与状态组件 |
| `apps/desktop/src/Inspector.tsx` | 修改 | 接入批量操作，使用最新上游任务 |
| `apps/desktop/src/App.tsx` | 修改 | 提供资料关联并应用批次工作流 |
| `apps/desktop/src/workbench.css` | 修改 | 白色界面中的批量操作布局 |
| `scripts/characters-smoke.mjs` | 修改 | 选择、批次状态与防重复回归 |
| `scripts/locations-smoke.mjs` | 修改 | 场景入口文案与交互回归 |

### 任务清单（必须全部标记完成）
- [x] 任务 1：组件输入提取结果、资料、工作流和任务，输出工作流配置；显示数量与完成/排队/生成中状态，有活跃任务时禁用提交。
- [x] 任务 2：Inspector 替换原始按钮，传入角色/场景资料；只使用最新上游任务结果，避免提取中使用旧结果。
- [x] 任务 3：App 传入资料，所选服务和工作流应用到本次独立节点，保留提示词、参考素材与已采用图片；提交锁生效时不修改节点。
- [x] 任务 4：CSS 为数量、说明、选择器和全宽按钮提供稳定布局，复用现有主题和焦点样式。
- [x] 任务 5：浏览器验证工作流继承、重复节点防护、活跃批次禁用及状态反馈，保存截图检查。
- [x] 任务 5b：批量创建节点后保留当前选中入口，输入原选中节点，输出可继续查看批次进度的属性面板；浏览器确认提交后面板仍可见。
- [x] 任务 6：类型、构建与回归通过，记录交付结果。

### 验收标准
- [x] 角色和场景均可在批量区域选择生成服务及适用工作流。
- [x] 按钮显示数量，提交中显示阶段，批次运行时显示状态并禁用重复提交。
- [x] 已采用图片继续保留，重新生成仍使用独立节点的重新生成入口。

### 风险点
批次状态依据当前提取任务关联的资料和节点；不同提取任务独立统计。缓存和已采用图片沿用现有运行逻辑，不强制重复收费生成。
