## 开发文档：素材图名称前缀

### 背景
多个角色和场景生成的图片需要通过素材名称直接辨认归属。

### 目标
- [x] 新生成角色图和场景图使用「名字_现有文件名」。
- [x] 多场景入口继续按场景分别生成四视图。

### 涉及文件
| 文件路径 | 操作类型 | 说明 |
|---------|---------|------|
| `services/backend/app/store.py` | 修改 | 图片入库时添加角色、场景或节点名称前缀 |
| `services/backend/tests/test_asset_names.py` | 新建 | 命名和文件存储不变的回归测试 |
| `scripts/locations-smoke.mjs` | 修改 | 验证多个场景提交全部独立节点 |

### 任务清单（必须全部标记完成）
- [x] 任务 1：图片入库命名；输入原文件名、节点关联，输出带名字前缀的素材名；角色/场景名字优先，缺失时用节点标题；导入素材、音视频保持原名。
- [x] 任务 2：测试中文、特殊字符、缺失关联、原文件名与扩展名保留、物理存储及引用不受影响。
- [x] 任务 3：浏览器模拟多个场景，验证生成全部提交每个场景的节点且重复点击复用。
- [x] 任务 4：运行回归，队列空闲后重启本地服务，验证接口。

### 验收标准
- [x] 角色图如「林夏_image_1.png」，场景图如「咖啡馆_image_1.png」。
- [x] 图片 ID、哈希、物理路径不因名称前缀发生改变；历史素材不迁移。
- [x] 多场景分别生成四视图，沿用共享媒体并发设置。

### 风险点
名称中的路径分隔符及 Windows 非法字符替换为下划线；保留原文件名；未关联名字的节点使用标题，无标题保留原名。缓存复用的历史素材继续保留历史名称。
