## 开发文档：刷新性能与目录选择

### 背景
大画布轮询会重复创建节点对象，数据目录只能手动输入，增加运行开销和配置负担。

### 目标
- [x] 保留未变化的任务、素材和节点对象，降低重复渲染开销。
- [x] 后台页面暂停轮询，恢复可见时立即刷新。
- [x] Windows 提供文件夹选择器，选择后不自动保存配置。

### 涉及文件
| 文件路径 | 操作类型 | 说明 |
|---------|---------|------|
| `apps/desktop/src/taskRefresh.ts` | 新建 | 索引任务并复用未变化状态 |
| `apps/desktop/src/taskRefresh.test.mjs` | 新建 | 变化、过期任务和大画布回归 |
| `apps/desktop/src/App.tsx` | 修改 | 接入合并逻辑与可见性轮询 |
| `services/backend/app/directory_picker.py` | 新建 | Windows 原生选择器，超时与并发控制 |

### 任务清单（必须全部标记完成）
- [x] 任务 1：实现任务状态合并；输入当前状态与服务端列表，输出复用引用的状态，任务按节点索引，保持最新任务和修改时间保护。
- [x] 任务 2：新增合并测试；输入重复、变化、过期和大量任务，验证只更新受影响节点且不覆盖新编辑。
- [x] 任务 3：接入画布轮询；输入请求结果与页面可见性，输出按需更新；不可见暂停、可见立即刷新，卸载清理监听。
- [x] 任务 4：实现目录选择器；输入当前路径，输出选择路径或取消；固定脚本、环境变量传参、不执行输入字符串、限制单个对话框。
- [x] 任务 5：测试目录选择逻辑；输入取消、错误、超时与特殊字符路径，输出可判断结果且不写入配置。
- [x] 任务 6：接入受认证 API；输入选择请求，输出可用性、选中路径或明确错误，原保存逻辑保持独立。
- [x] 任务 7：设置页添加选择按钮；输入选择结果，仅更新输入框；取消保持原值，忙碌禁用操作。
- [x] 任务 8：扩展浏览器验收；模拟原生选择响应验证填入、取消和未自动保存，真实后端验证已有保存功能。
- [x] 任务 9：将新前端测试加入 verify，运行构建、前后端测试，记录结果。

### 验收标准
- [x] 相同轮询响应不触发状态引用更新，修改后只替换相关节点。
- [x] 新编辑不被旧任务覆盖，后台轮询有清理和恢复逻辑。
- [x] 选择目录不修改保存配置，仍需保存并重启。
- [x] 目录 API 需要认证，用户路径不会作为脚本执行。

### 风险点
- 暂保留可见页面完整列表请求，避免遗漏素材改名和删除；本次不宣称服务端增量同步。
- Windows 选择器使用系统 PowerShell/.NET，限制环境需手工输入；非 Windows 隐藏入口。
- 原生交互取消不应显示错误；超时必须清理启动的进程。
- 不自动迁移旧项目，不打包或发布 EXE。
