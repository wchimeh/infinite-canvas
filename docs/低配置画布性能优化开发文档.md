## 开发文档：低配置画布性能优化

### 背景
多节点端口重复扫描、大量候选 DOM 和视频封面并发解码会增加低配置电脑的 CPU 与内存压力。

### 目标
- [x] 节点共享连线、任务和素材索引，减少更新时重复扫描。
- [x] 候选列表仅渲染可见区域，保留完整搜索、滚动、键盘与自动连线。
- [x] 视频封面最多同时运行一个解码任务，限制线程并合并相同素材请求。
- [x] 记录正常及 CPU 降速场景的性能与功能验证结果。

### 验收标准
- [x] 同一连线数组只构建一次端口索引，修改连线后正确更新且动态端口上限不变。
- [x] 1000 个候选时 DOM 中不超过 12 个候选按钮，滚动、搜索和键盘可访问首尾来源。
- [x] 4 倍 CPU 降速下候选弹框可打开、搜索及连接，无页面错误。
- [x] 多个视频缩略图请求最多一个解码子进程，显式限制线程，同一文件并发只解码一次。
- [x] 图片、音频、视频、文本连接、替换、撤销及手动拖线保持正常。
- [x] 记录本机测量结果，不将 CPU 降速模拟当作低配置实体电脑的保证。

### 风险点
- WeakMap 索引依赖项目已有的不可变状态更新规则，缓存不应阻止旧数组回收。
- 虚拟列表需要固定行高和焦点管理，避免长标题、滚动或键盘导致错项。
- 串行解码降低资源峰值但冷封面可能稍后出现，热缓存读取不应排队等待。
- 现有工作区改动较多，仅增量调整本文涉及逻辑，不修改日常项目或调用云端。

### 验证结果
- 前端 32 项单元测试通过，后端缩略图 12 项测试通过；并发测试验证旧实现会同时解码 4 个任务，新实现峰值为 1，相同文件仅解码一次。
- `pnpm build`（含 TypeScript 检查）通过；语法检查 86 个 Python 文件、43 个 JavaScript 脚本通过。仍有已有的主包体积提示和测试依赖弃用提示。
- 输入点浏览器回归、连接命中范围回归、1000 候选性能验收均通过；验证首尾滚动、键盘 Home/End/上下键、全量搜索、连线、撤销、图片及视频封面、加载失败回退和概览放大恢复。
- 已复核视频候选及 200 节点概览截图；低于 50% 时暂时隐藏预览细节，节点尺寸及端口位置保持不变，放大恢复。
